# 2026-10 UI 优化方案（三阶段，已批准执行）

> 来源：2026-10-12 前端/UI 全面审计。原则：**不换设计语言**——"Pulse Console"（双主题 token + WCAG 测试 + 11 组动画）是资产，只补结构性欠账、提执行精度。

## 审计证据（不动手的强项 / 要修的欠账）

强项：token 体系完整且双主题对应；对比度有测试把关；动效成体系且 reduce-motion 双保险；confetti 已分包（主包 107KB gzip）。

欠账：
1. **键盘可达性**：1065 行 CSS 仅 1 处 `focus-visible`，Tab 用户盲走。
2. **样式三层混杂**：79 处内联 style + 73 处 Tailwind 任意值；字号 10.5~34 共 14 种，无刻度。
3. **右侧台面**：限宽 620 居中导致大屏两侧空白；「紧随其后」不可点；语录静止。
4. **移动端**：仅 768px 一个断点；<769 完全没有「当前该做什么」视图；420px 停靠窗被当手机。

## 阶段 1 · 修地基（可达性 + 设计刻度）

- 1.1 全局 `:focus-visible` 焦点环（`--accent-focus` token，鼠标用户不可见）。
- 1.2 字号刻度：14 种 → 8 档（`--fs-2xs/xs/sm/base/md/lg/xl/2xl`）+ `.ap-t-*` 工具类，全组件清扫（text-[Npx] 与内联 fontSize 全部指向 token）。
- 1.3 重复内联样式归拢为组件类（`.ap-btn--sm/--cta`、`.ap-select--sm`、`.ap-input--sm`）。
- 验收：纯 Tab 走完全流程焦点可见；视觉零回归；typecheck + 316 测试全绿。

## 阶段 2 · 精度打磨

- 2.1 「紧随其后」可点：`onFocusTask(id)` → `setFocusIntent({kind:"task", pinnedTaskId:id})`（复用盲盒机制）。
- 2.2 台面放宽 620→820，统计改环形四周网格。
- 2.3 卡片 stagger 入场（index×30ms 封顶 5，尊重 reduce-motion）。
- 2.4 `MiniStage` 紧凑台面条：<769 布局顶部一行「能量环+当前任务+聚焦」，手机与停靠窗共用（同时交付 3.1 的移动端概览）。
- 2.5 台面语录 9s 轮换（ap-fade）。

## 阶段 3 · 方向性投资

- 3.1 移动端概览 —— 由 2.4 MiniStage 覆盖（能量+当前任务+习惯同屏）。不做底部 Tab（违背"打开就知道做什么"）。
- 3.2 首次运行演示卡：空态且累计完成 <3 时出现可交互示例勾选（触发礼花+提示，不污染数据）。
- 3.3 PWA：`beforeinstallprompt` 捕获 → 应用内安装横幅；sw.js 增加 `SKIP_WAITING` + `controllerchange` 刷新 toast。
- 3.4 i18n：LanguageContext + zh/en 字典 + `t()` 类型安全（keyof 守卫）+ 设置切换（per-device，不同步）；战报 Markdown 保持中文（生成物属个人数据）。

## 明确不做

标签/项目/循环任务；换设计语言；底部 Tab 导航。
