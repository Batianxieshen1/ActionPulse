## A 卖点诚实度（最高优先）

### A1 把评分分解搬上卡片 ✅

- **证据**：`src/ui/` 层对 `rawScore / dueFactor / ageFactor` 零引用（grep 验证）。README 承诺「卡片上直接告诉你各分项贡献了多少」（EN: "the card shows which component contributed what"），实际只有总分徽章 + hover 档位提示。头号卖点没有到达用户的路。
- **改法**：
  1. `src/domain/urgency.ts` 新增 `urgencyComponents(task, today)`，返回 `{ imp, due, quick, age, total }`（各分项的加权原始分）；`rawScore` 改为复用它（行为不变）。
  2. `tests/urgency.test.ts` 新增：分项之和 === rawScore；一个已知任务逐项断言。
  3. `src/ui/TaskCard.tsx` 展开详情顶部新增「为什么是这个分数」区块：四行 `标签 · 得分 · 条形`，条形按**各分项相对自身理论满分**（35 / 48 / 15 / 10）的占比填充；末行合计 `合计 56.5 / 108 → 紧迫度 52 分`。
  4. `src/index.css` 新增 `.ap-breakdown*` 样式，只用既有 token（双主题自动成立）。
  5. 两版 README 措辞改为「展开卡片详情，各分项贡献一目了然」（从"卡片上"收窄到真实位置）。
- **验收**：测试全绿；浏览器实测高优 + 超期任务的分解条与手算一致。

### A2 聚焦模式全清文案 ✅

- **证据**：`FocusStage.tsx:275-291` 只有一个空态分支。录制实测：把最后一件点「完成了」，屏幕显示「候选都被你跳过了」+「重新看一遍」——完成被说成跳过，成就感时刻说错话。
- **改法**：`tasks.length === 0`（待办池已空 = 全部完成）→ 文案「清单清空了」/ 副句「今天想做的都做完了——休息一下吧」/ 只留「回到清单」；否则保留现有「候选都被你跳过了」与双按钮（该文案在纯跳过场景是对的）。
- **验收**：浏览器实测两条到达路径的文案与按钮。

### A3 同步合并的 README 措辞对齐实现 ✅

- **证据**：`merge.ts` 的 `pickNewer` 对任务是**整对象**二选一，仅习惯才是字段级合并；README（中英）写「每个任务按字段做后写胜出」，承诺强于实现。两台设备同时改同一条任务的不同字段时，较新整条胜出、另一侧字段改动丢失。
- **改法**：README 改为「每个任务按 `updatedAt` 整条后写胜出；习惯的完成记录按只增集合逐字段合并」。实现不动（个人规模下整条 LWW 的简单性是刻意取舍）。
- **验收**：两版 README 与 `merge.ts` 行为一一对应。

## B 界面细节（中优先）

### B1 QuickAdd：被标记接管的下拉框视觉弱化 ✅

- **证据**：录制帧显示——胶囊写「高优」，正下方下拉框仍是「普通」，双事实源并存。
- **改法**：三个下拉**逐字段**判断（不能整行弱化：标记只覆盖部分字段时其余下拉仍然生效）：被标记接管的字段 `disabled` + 半透明 + `title="已由标题里的标记指定"`；删掉标记即恢复。
- **验收**：浏览器实测 `!high 今天 ~5m` 三框分别置灰、删标记恢复。

### B2 聚焦台面：番茄钟「开始」按钮去主色 ✅

- **证据**：台面上「完成了」与「开始」同为 `data-variant="primary"`，主行动被稀释；自动化选选择器时也在此发生 strict 冲突（本条修完，台面 primary 唯一，顺带消除冲突）。
- **改法**：`FocusStage.tsx` 番茄钟「开始」按钮去掉 `data-variant="primary"`（保留默认样式；「续杯」按钮在 refill 场景出现，保持 primary 不变——那是它自己的主行动时刻）。
- **验收**：进入聚焦台面目视只有一个绿色主按钮。

### B3 面板空态与台面空态合并叙事 ✅

- **证据**：清空状态下面板卡片「清单是空的」与台面「清单见底了」同屏，两套措辞。
- **改法**：面板侧降为单行弱提示（保留"写下第一件事就行"的引导，去掉卡片盒子）；台面保留完整主叙事。
- **验收**：清空状态目视一主一辅。

### B4 顶栏两组控件加维度分隔 ✅

- **证据**：`Header.tsx:125-173` 清单/四象限（视图）与 智能/手动（排序引擎）是两个维度，但同排同样式。
- **改法**：两组之间加一条细竖分隔线（token 化颜色），第二组前的 `ml-auto` 保留。
- **验收**：目视两组有"维度分界"暗示。

## C 工程加固（中优先）

### C1 战报「专注时长」加合并策略脚注 ⬜

- **证据**：`daily.focusMinutes` 多端合并取最大值（dev-log 已记录取舍），但战报界面未说明——用户自己发现"数字少了"会伤信任。
- **改法**：`DebriefSheet.tsx` 专注时长行下加小字「多端之间取较大值合并——宁可少算，不做虚高」。
- **验收**：战报目视脚注；文案与 dev-log 表述一致。

### C2 服务端冒烟测试 ⬜

- **证据**：`npm start` → `/api/health` → 鉴权 → 存取这条链无任何自动化守护（`lan.test.ts` 只测地址收集）；SW 事故的教训是"测试全绿 ≠ 链路通"。
- **改法**：`tests/serverSmoke.test.ts`：spawn `node server/index.mjs`（随机高位端口 + 临时 `AP_DATA_DIR`）→ 轮询 `/api/health` 期待 200 与 `ok:true` → 无 token `PUT /api/state` 期待 401 → 结束 kill + 清理临时目录。
- **验收**：`npm test` 在本地与 CI 都稳定通过（约 +4 测试）。

## E 产品闭环（高优先）

### E1 战报新增「近 7 天估时分布」 ⬜

- **证据**：`docs/dev-log/q-factor-tradeoff.md` 的观察项（速赢因子是否让人捡芝麻）需要数据回路；`Task.completedAt` 字段已存在（v2 即有），**零 schema 变更**。
