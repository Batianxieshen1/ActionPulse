# 部署与多端同步指南

这份文档回答一个问题：**我想在哪些场景下用 ActionPulse，该选哪种部署形态？**

先记住一条，它能省掉很多弯路：

> **前端（页面）放在哪里都无所谓，后端（同步服务）必须有一个，而且两台设备都得够得着。**

前端是「工具」，后端是「信箱」。工具可以放在任何地方；信箱必须有，且双方都能连上。

读代码也能确认这一点：客户端的同步地址就是它自己被打开的地址。

```ts
// src/sync/session.ts
return { baseUrl: window.location.origin, token };
```

## 形态一：只有本机（默认）

```bash
npm start
```

打开 `http://localhost:5273/?token=<token>`。数据在 `./data/state.json`。

`localhost` 属于**安全上下文**，所以这个形态下 Service Worker 会注册，离线缓存可用。

## 形态二：局域网多端

不需要任何额外配置。服务默认监听 `0.0.0.0`，终端会打印手机可用的地址：

```
  ├─ 手机:   http://192.168.1.42:5273/?token=<token>
```

手机连**同一个 Wi-Fi**，打开这个地址即自动完成配对（token 会被存下来并立刻从地址栏抹掉）。

### 连不上时的排查顺序

| 症状 | 原因 | 处理 |
| :--- | :--- | :--- |
| 无法访问 / 一直转圈 | 手机在用流量，或连了别的 Wi-Fi | 确认是同一个 Wi-Fi |
| 同上 | 手机开着 VPN / 代理 | 关掉再试（私有网段常被代理吞掉） |
| 同上，VPN 也关了 | 路由器开了 **AP 隔离 / 客户端隔离** | 换主 Wi-Fi，或关掉路由器里的隔离 |
| 同上，且是**校园网 / 酒店 / 公司网** | 这类网络普遍禁止客户端互访 | 见下方「绕过受限网络」 |
| 页面能开但显示离线 | token 不对 | 设置 → 同步，手动粘贴 token |
| 隔几天突然连不上 | 路由器 DHCP 换了 IP | 给这台电脑做一条 DHCP 保留 |

### 绕过受限网络（校园网 / 公共 Wi-Fi）

这类网络几乎一定会禁止客户端之间互访（有的允许 ARP 让邻居可见，但封掉所有客户端之间的 TCP）。**这不是你的配置问题，改设置也没用。**

可靠的绕法只有一条：**让两台设备之间走一条这个网络管不到的私有链路。**

| 办法 | 做法 | 优点 | 缺点 |
| :--- | :--- | :--- | :--- |
| **USB 网络共享**（推荐） | 数据线连手机与电脑，手机开启「USB 网络共享」 | 电脑**还能继续用原网络**上网；链路稳定 | iPhone 需要装过 iTunes 驱动 |
| 手机开热点 | 电脑连手机热点 | 零配置 | 电脑离开原网络，改用手机流量 |
| 蓝牙网络共享 | 蓝牙配对后共享 | 无线 | 慢 |

开启之后电脑会多出一张网卡，地址会变——**不要继续用原来那个 IP**。重新看终端输出，或者用 `npm start` 再打印一次。

## 形态三：随时随地

要让手机在 4G、在外面咖啡馆也能同步，需要一条从「手机所在网络」回到「你的服务」的通路。三种做法：

### 方案 A：私有 mesh VPN（Tailscale / ZeroTier）

电脑和手机各装一个客户端，加入同一个虚拟内网。手机会拿到一个**固定的虚拟地址**，从此从任何网络都能访问电脑。

```
  Phone (4G) ──┐
                ├──► mesh VPN ──► your machine:5273 ──► ./data/state.json
  Laptop ──────┘
```

- 不需要公网 IP、不需要改路由器，能穿透 NAT / CGNAT
- 用 `tailscale serve`（**只有你自己的设备能访问**），**不要**用 `funnel`（那是公开到公网）
- 顺带拿到 HTTPS，于是 [HTTPS 的三个附带好处](#https-的三个附带好处) 全部生效
- 电脑必须开机；关机时手机仍可离线使用，等电脑醒来再对齐

> **实测说明**：这类工具的协调服务器多在境外，国内可能出现延迟高或不稳定的情况，需要实际试。国内的商业组网服务（蒲公英、贝锐等）能做同样的事，代价是付费。本项目**未在真机上验证过任何一款组网工具**。

### 方案 B：Cloudflare Tunnel 之类

`cloudflared` 不需要公网 IP、能穿 CGNAT，直接给一个 HTTPS 域名。

代价是**数据会经过第三方边缘节点**。可以再叠一层 Cloudflare Access（邮箱验证码）做鉴权。

### 方案 C：把服务端部署到一台小主机

整个 `server/` 只有一个 Node 脚本、**零 npm 依赖**，可以直接放到任何装了 Node 的机器上：

```bash
node server/index.mjs            # 默认 5273
PORT=8080 AP_DATA_DIR=/data node server/index.mjs
```

需要准备的只有两件事：

1. **一个持久化卷**挂到 `AP_DATA_DIR`——否则重启后数据会丢。
2. **HTTPS**（用平台自带的，或前面放一层反代）。

好处是电脑可以关机，一个地址同时提供页面和 API（**同源，因此不需要改动任何代码**）。

代价是持续支出，且数据在你租的机器上。

## 静态托管为什么不行

GitHub Pages、Vercel、Netlify 这类服务**只能托管静态文件，跑不了 Node 服务**。

把 `dist/` 直接部署上去会发生两件事：

1. **页面可能是坏的。** Vite 默认用绝对路径引用资源（`/assets/...`）。项目型 Pages 地址是 `https://<user>.github.io/<repo>/`，绝对路径会全部 404，除非在 `vite.config.ts` 里配置 `base`。
2. **同步一定是死的。** 客户端会去请求 `https://<user>.github.io/api/state`——那里没有这个接口。两台设备各自存在各自的浏览器里，**永远不会相通**。

第 2 点比「连不上」更危险，因为它**静默分叉**：两边看起来都正常，你不会发现哪个才是最新的。

如果你确实想把页面放静态托管，需要在代码里额外做三件事：配置 `base`、把同步地址从「写死等于页面域名」改成**可配置**、并给服务端加上 **CORS**。另外页面是 `https` 而本地服务是 `http` 时，浏览器会按**混合内容**拦掉请求，所以后端也必须提供 HTTPS。

**结论**：静态托管解决不了同步问题，却要多改三处代码。想随时随地，直接用方案 C 更省事。

## 为什么不要用端口转发

把 5273 端口通过路由器转发到公网，看起来是最直接的做法。不推荐，原因有三：

1. **本地服务默认是纯 HTTP。** 配对 token 会在公网上明文传输，截获者可直接读写你的全部数据。
2. **这是个个人工具，不是一个加固过的公网服务。** 它只有一个配对 token，没有账号体系、没有速率限制、没有封禁、没有审计日志。暴露到公网不是一个好主意。
3. **很多家宽根本没有独立公网 IPv4**（CGNAT 大内网），端口转发做了也不通；部分地区还会封锁入站 80/443。

如果确实需要从公网访问，请用方案 A 或 B——它们都会顺带提供 HTTPS 和一层身份验证。

## HTTPS 的三个附带好处

浏览器只把 `https://` 和 `localhost` 当作**安全上下文**。手机通过 `http://192.168.x.x` 访问时不是，于是：

| 功能 | 局域网 HTTP | 换成 HTTPS 后 |
| :--- | :--- | :--- |
| 离线缓存（Service Worker） | 不注册，断网打不开 | 可用 |
| 一键复制战报 | `navigator.clipboard` 被禁用，降级到 `execCommand` | 使用原生剪贴板 |
| 「添加到主屏幕」 | 只是个书签快捷方式 | 真正的 PWA |

注意：**同步、界面、音效、习惯、战报在 HTTP 下全部正常**，受影响的只有上面这三项。

## 数据与安全

| 项目 | 位置 | 是否进版本库 |
| :--- | :--- | :--- |
| 任务与习惯数据 | `./data/state.json` | 否（`.gitignore` 已排除） |
| 配对 token | `./data/token.txt` | 否 |
| LLM 配置与密钥 | `./data/llm.json` 或 `.env` | 否 |

- 配对 token 存在浏览器的 localStorage 里，配对成功后立刻从地址栏移除（避免截图或分享时带出去）。
- LLM 的 API Key **只存在于服务端**，界面上只回显掩码形式。
- 忘记 token 时删掉 `data/token.txt` 重启，会重新生成一个，然后在各设备上重新配对。
- 想要把某台设备踢下线，重新生成 token 即可。
