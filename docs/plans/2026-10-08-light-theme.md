# 浅色模式（白天模式）实施计划

**目标**：在现有纯深色应用上增加一套浅色主题，可在「跟随系统 / 浅色 / 深色」三档间切换并记住选择；两套主题都通过 WCAG AA 对比度校验。

**一句话结论**：能做，属中等工作量。成本不在「想颜色」，而在**把 43 处散落在样式表里的硬编码颜色收敛成令牌**——现有令牌层只覆盖了大约一半的界面。

## 二、为什么不能「反转颜色」——实测对比度

现有 9 个颜色令牌在深底（`#06070a`）与白底上的 WCAG 对比度：

| 令牌 | 色值 | 深底上 | 白底上 | 白底判定 |
| :--- | :--- | ---: | ---: | :--- |
| `--pulse`（主色） | `#c8f751` | 16.19 | **1.24** | ❌ 等于隐形 |
| `--tier-critical` | `#ff5252` | 6.31 | **3.19** | ⚠️ 只够大字/图形 |
| `--tier-high` | `#ff9f45` | 9.88 | **2.04** | ❌ 不可用 |
| `--tier-medium` | `#4cc9f0` | 10.47 | **1.92** | ❌ 不可用 |
| `--tier-low` | `#64748b` | 4.23 | 4.76 | ✅ |
| `--text` | `#e9edf4` | 17.16 | **1.17** | ❌ |
| `--text-dim` | `#97a1b2` | 7.73 | **2.61** | ❌ |
| `--text-faint` | `#5c6675` | 3.47 | 5.81 | ✅ |
| `--teal` | `#5eead4` | 13.62 | **1.48** | ❌ |

**9 个里 6 个在白底上不可用。** 主色对比度 1.24:1（正文要求 4.5:1），意味着那套「亮电光柠檬」的基因在白底上根本不成立。
所以浅色必须**重新设计一套配色**，而不是把值换一换。

（顺带一个有意义的发现：`--tier-low` 与 `--text-faint` 在白底上反而合格——它们本来就是深色系里偏暗的两个。）

## 三、浅色配色候选（已实测对比度，底色 `#f7f7f4`）

| 用途 | 候选 | 对比度 | 判定 |
| :--- | :--- | ---: | :--- |
| 主色（强调 / 主按钮 / 能量条） | `#4a6b00` 深橄榄 | 5.76 | ✅ |
| 主色 hover | `#3d5900` | 7.45 | ✅ |
| 重要且紧急 | `#c02626` | 5.52 | ✅ |
| 重要不紧急 | `#9a5a00` | 5.10 | ✅ |
| 紧急不重要 | `#0b6b8a` | 5.62 | ✅ |
| 不重要不紧急 | `#5b6673` | 5.45 | ✅ |
| 正文 | `#1a1d23` | 15.73 | ✅ |
| 次要文字 | `#4b5560` | 7.07 | ✅ |
| 弱化文字 | 约 `#646d79` | 4.11 ~ 5.45 之间 | 由自动测试锁定「最浅仍达标」的值 |

**底色刻意不用纯白**：用 `#f7f7f4`（暖白），卡片反而用 `#ffffff` 提亮。这样「卡片浮起」靠的是明度差，而不是深色版那种白色半透明叠加——两套主题的层次感用不同手法实现，观感才各自成立。

## 四、实施步骤

### 步骤 1　把颜色收敛成令牌（**不改外观**，纯重构）

- 补齐缺失的语义令牌（约 20 个），逐条替换那 31 处 + 5 处硬编码
- 完成后：样式表与组件里**没有任何绕过令牌的颜色**
- 验收：深色模式截图与重构前**逐像素一致**
- 沿用现有命名风格（不加前缀），避免制造无意义的重命名 diff
- 这是唯一有回归风险的一步，所以单独成步、单独验收

### 步骤 2　拆出主题块

- `:root` 只留与主题无关的**结构**（圆角、字体、安全区）
- `[data-theme="dark"]` 与 `[data-theme="light"]` 各放一套**颜色**令牌
- 加 `color-scheme: dark / light`，让原生控件、滚动条、表单自动跟随

### 步骤 3　切换 + 持久化 + 不闪屏

- `Settings` 新增 `theme`（取值 `system` / `light` / `dark`），默认 `system`
- 新增 `useTheme`：解析系统偏好、监听 `matchMedia` 变化、写 `data-theme`
- **防闪屏**：`index.html` 的 `<head>` 里放一段内联脚本，在首次绘制前读 localStorage 设好 `data-theme` 与 `theme-color`（等 React 挂载才设的话，浅色用户会先闪一下深色）
- 动态更新 `<meta name="theme-color">`，否则浅色模式下手机状态栏仍是近黑
- 设置界面加一档「主题」
- **主题不跨设备同步**：手机想浅色、电脑想深色是合理的，与现有「设置保持设备本地」的规则一致

### 步骤 4　非 CSS 资产主题化

- 礼花：两套配色（浅色下 `#ffffff` 与 `#eaff9a` 直接看不见）
- SVG 圆环轨道 / 勾选框 / 扫光 → 走令牌
- shell 三处光晕在浅色下换成「淡墨晕」配方
- 颗粒噪点降低不透明度

### 步骤 5　验证（见第五节）

## 五、验证方案（这部分决定它算不算做完）

1. **自动对比度测试**（新增 vitest 单测）
   - 读取两套令牌表，逐对计算 WCAG 对比度
   - 断言：正文类 ≥ 4.5:1，大字 / 图形 / 边框类 ≥ 3:1
   - 覆盖组合：文字×底色、文字×卡片底、四档紧迫度×卡片底、主色按钮文字×主色底、主色×底色
   - **这是唯一能防住「以后随手改个色就把可读性改坏」的机制**
2. **深色零回归**：步骤 1 前后各截一组图，逐像素比对
3. **浅色端到端**（Playwright）：两主题各截桌面 + 手机图，并断言无残留深色元素
4. **切换链路**：三档切换生效、刷新后保持、模拟系统主题变化时「跟随系统」档实时响应、**首屏不闪**
5. **移动端 + 安全区**在浅色下同样正确（复用现有 iOS 检查脚本）

## 七、明确不做（YAGNI）

- 不引入 primitive → semantic → theme 的三层设计系统：现有 22 个语义令牌 + 新增约 20 个已经够用，再分层只是多一层间接
- 不引入 Tailwind `dark:` 体系：现有代码零 `dark:` 用法，两套机制并存会让「这个颜色到底谁说了算」变模糊
- 不做第三套自定义主题、不做主题色可调
- PWA manifest 的 `background_color` / `theme_color` 是**静态**的（安装后的启动闪屏用），无法随主题变化——这是真实限制，我会写进文档而不是假装解决
- 删掉 `<html class="dark">`（死代码）

## 八、需要你拍板的三点

### ① 默认主题
- **推荐：跟随系统**（首次打开跟随操作系统）
- 或：固定深色（保持现在的观感，浅色手动切）

### ② 浅色的设计方向（唯一一个审美决策）

| | 方向 | 底色 | 主色 | 气质 |
| :--- | :--- | :--- | :--- | :--- |
| **A（推荐）** | 日光工作台 | 暖白 `#f7f7f4` | 深橄榄 `#4a6b00` | 保留「脉冲柠檬」的血统，像摊在桌上的一张好纸 |
| B | 冷灰专业 | 冷灰 `#f4f6f9` | 深青蓝 `#0b6b8a` | 更像 SaaS 工具，冷静克制 |
| C | 纯白极简 | 纯白 `#ffffff` | 近黑作主体，橄榄只做强调 | 最克制、对比最高、最没有设计痕迹 |

我推荐 **A**：深色版的签名是那条电光柠檬脉冲线，A 是唯一能让它在浅色下**仍认得出是同一个产品**的方向。

### ③ 要不要「跟随系统」这一档
- **推荐要**。代价是必须处理防闪屏与系统主题切换监听，我已算进步骤 3
- 不要的话就是两档手动，少约一个子步骤

---

## 九、顺序与可停点

每一步都能独立验收、独立停下：

1. 步骤 1（令牌收敛）→ 深色截图回归通过 → **可停**
2. 步骤 2 + 3（浅色令牌 + 切换）→ 浅色能看能用 → **可停**
3. 步骤 4（礼花 / 光晕 / 圆环）→ 细节也一致
4. 步骤 5（对比度测试 + 全量 E2E）→ 收尾

建议**一次做到第 5 步**：步骤 1 如果只做一半，后面每加一个浅色样式都会再引入一批新的硬编码。
